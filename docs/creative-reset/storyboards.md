## Three meaningful signature interactions

1. **Open section:** one aperture links identity, project viewport and system structure. The shape carries narrative continuity. Prototype CSS/SVG before considering WebGL. Test matching boundaries in forward and reverse scroll; phone uses a separate vertical timeline.
2. **Request lens:** choose one real Kerasobha enquiry path. Interface → validation / idempotency at the edge → persistent record → email retry responsibilities, described only to the level supported by project data. Explicit controls, `aria-pressed`, live description and a linear alternative. No invented traffic or performance metrics.
3. **Evidence window:** project image and decision stay spatially aligned as the visitor chooses Story / Interface / Structure. Real screenshots with captions replace generic device mockups; the case-study link never moves out of reach. Phone gets one large stage and three thumb-sized buttons, desktop an editorial index.

These interactions form one opening/section vocabulary rather than three disconnected visual tricks.

## Optional production assets — only after approval

Every proposed prompt below assumes a separately approved identity reference and portrait treatment. Never generate a face from a name. Use owner originals or approved identity-preserving edits, review opening/mid/closing frames for facial consistency, and reject changed proportions, skin artifacts or wardrobe drift before encoding. Google Flow access has not been checked for this reset; use only if available and explicitly authorized. New photography is equally valid.

Common direction: natural skin, contemporary everyday tailoring, neutral studio or architectural environment, practical daylight, no wealth symbolism, no text, no software UI, no logos, no artificial facial/body changes. Desktop 16:9 and phone 9:16 are independently composed shots, not automatic center crops. Clips are silent.

All footage needs reviewed poster frames, explicit dimensions, MP4/WebM as justified by actual browser support, a light still alternative and no dependency on playback for content. Loading is gated by viewport, connection preference and reduced motion. Do not use `currentTime` scroll scrubbing until seeking/decode tests prove reliable on the target phones; a masked still or short bounded playback is the default prototype.

## Architecture and budgets for approved production

- Shared verified content, tokens, project metadata, accessibility utilities and motion primitives. Separate desktop/phone hero, navigation, project gallery and complex system presentation where composition requires it. Match-media lifecycle mounts one active branch and cleans up GSAP/ScrollTrigger, media listeners and videos.
- Start with React/Vite/TypeScript already present. Use existing GSAP when full timeline work begins. Introduce Three.js only for a specific approved effect that DOM/SVG cannot achieve convincingly.
- Proposed starting budgets: opening image ≤250 KB where portrait quality allows, mobile hero footage ≤1.5 MB, no media-heavy duplicate branch, no active offscreen animation, and no extra canvas loop at idle. These are targets to validate, not observed results.
- Measure transferred bytes, LCP, CLS, responsiveness, CPU and dropped frames on a representative Android phone and desktop. Lab metrics need named devices/settings; no field claims without field data.
- Require mobile composition and timeline approval before expanding the full desktop build. Then deliver one case study, validate evidence and accessibility, and expand the remaining narrative.
